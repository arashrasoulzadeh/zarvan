# API عامل: `Behavior` و `WorldView`

رابطی که به یک عامل (اسکریپت، قانون‌محور، یا مبتنی بر LLM) اجازه می‌دهد یک موجودیت را در زمان اجرا هدایت کند، با تفکیک مشاهده و کنش. این رابط مرز امنیتی برای کد Dart غیرقابل‌اعتماد نیست.

## چرا تفکیک مشاهده و کنش؟

اگر یک Behavior می‌توانست `World` را آزادانه تغییر دهد، یک باگ یا یک فراخوانی بد LLM می‌توانست ناوردایی‌های سیستم‌های دیگر را بشکند. قرارداد پیشنهادی این است که Behavior از `WorldView` برای مشاهده استفاده کند و با برگرداندن یک `Action` تغییری **پیشنهاد** دهد. کد Dart مورد اعتماد می‌تواند به جهان قابل‌تغییر دسترسی داشته باشد. `AISystem` آن را روی جهان واقعی اعمال می‌کند.

```text
Behavior.decide(WorldView, EntityId self) -> Action
                                               |
                                               v
                                  AISystem: action.apply(world)
```

## سه راه برای کنش

1. **مغز یک موجودیت (بی‌درنگ):** پیاده‌سازی `Behavior`.
2. **بازیکن (نوبتی):** خواندن جهان به‌صورت JSON و ارسال `Order` با `submitOrder`.
3. **نویسنده/اپراتور:** عملیات روی MCP، REST، JSON-RPC یا CLI (`zarvan`).

**محدودیت امنیتی:** `WorldView.world` به جهان قابل‌تغییر دسترسی می‌دهد و componentها ممکن است قابل‌تغییر باشند. رفتارها به‌ترتیب اجرا می‌شوند؛ این نما یک snapshot ثابت نیست. برای عامل خارجی، مشاهده‌ها را فیلتر کنید و فقط عملیات مجاز را ارائه دهید.

## قواعد

- هرگز storeها را از بیرون system مالک آن‌ها تغییر ندهید.
- پیش از نوشتن بخوانید؛ پیش از اجرا اعتبارسنجی کنید (`zarvan lint`، `project.problems`).
- از `world.random` و گام ثابت استفاده کنید؛ از زمان ساعت دیواری در شبیه‌سازی استفاده نکنید.

## کشف عملیات و اعتبارسنجی

ابتدا `engine.capabilities`، سپس `engine.operations` و برای هر عملیات `engine.operation` را فراخوانی کنید. طرح‌وارهٔ ورودی و خطاها را از رجیستری جاری بخوانید؛ نام پارامترها را حدس نزنید. برای `world.patch` ابتدا `dryRun: true` و سپس، در صورت موفقیت، `strict: true` را به‌کار ببرید. در Dart از `world.checkPatch(patch)` پیش از `world.applyPatch(patch, strict: true)` استفاده کنید.

گزینهٔ `--read-only` عملیات دارای نوع نوشتن را محدود می‌کند، اما عملیات خواندنی مانند `world.step` و `world.patch` می‌توانند جهان درون حافظه را تغییر دهند. برای دسترسی صرفاً مشاهده‌ای، فهرست مجاز عملیات را در سرور محدود کنید. عملیات جهان نیازمند یک فرایند پایدار MCP/HTTP است؛ فراخوانی‌های جداگانهٔ CLI جهان مشترکی ندارند.
