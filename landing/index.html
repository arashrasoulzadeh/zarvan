The engine
Everything starts with the world.
Simulation, rendering and genre systems are separate layers, so the core stays portable, fast and testable.

      

        
01 / CORE
Deterministic simulation
Fixed timesteps, seeded randomness, ECS and headless tests. Run the exact same world on a phone, a server or CI.

        
02 / SHELL
Flutter at the edge
Rendering, input, audio, camera and platform services live in a thin shell. Gameplay never depends on Flutter.

        
03 / DATA
Content as data
Serialize worlds to JSON, author levels and dialogue as data, and keep each genre in a focused package.

      

    


    

      
A frame in three steps
Simple enough to reason about.
The loop is visible: every tick has a clear boundary between input, simulation and presentation.

      

        
01 · Observe
Read input, commands or an agent WorldView — without changing authority.

        
02 · Simulate
Advance ordered systems with a fixed timestep and deterministic rules.

        
03 · Present
Let Flutter render the resulting world and wire up platform services.

      

    


    

      

        Agent-native by design
        
Let agents play without giving up authority.

        
Agents observe a read-only view and propose actions. The engine validates and applies them. State can be logged, replayed, evaluated and patched as ordinary JSON — over MCP or HTTP.

        

          
ObserveCompact WorldView, no mutation.

          
ActMove, attack, build — via the operation registry.

          
EvaluateReplay the same JSON in CI or a benchmark.

          
AuthorPatch levels, dialogue and entities as data.
